# Publishing a Taco to a Host
Open this reference only for explicitly requested remote publication. Local Taco assembly, local toolbox usage (`new`, `init`, `pack`, `verify`, `refresh`, `diff`, `inspect`, `extract`, `open`, `listen`), and local review work offline without requiring a remote Host or account.
1. Read `taco-cli help publish` for the installed binary's current arguments and output. Choose the intended Host with `--host <origin>` or `TACO_HOST_URL`; current CLI releases default to the official service (https://taco.arcadia-han.com), but consult installed help because older releases default to a local Host.
2. Inspect the `.taco.html` locally for secrets and collaboration credentials before sharing it. A collaboration-enabled file can contain credentials; do not transmit the complete file to an external service or model without authorization. Hosted Tacos, comments, revisions, and assets are public by default.
3. Run `taco-cli publish <file.taco.html> --host <origin> --dry-run`. This projects and validates locally; examine its file list, `contentHash`, and `payloadBytes`. The dry run sends no network request.
4. If the projected content is safe and publication was requested, run the same command without `--dry-run`. The Host returns a `url` for the reviewer, a `tacoId` for subsequent event reads, and the initial `revisionId` and `contentHash`; record all of them. Share the `url` with the reviewer. A publication creates a new hosted Taco and does not change canonical local files: Tacobin supplies its own hosted review shell; the installable local shells do not contain hosted collaboration code. Hosted visitors can edit the shared review under self-reported names; edits and comments autosave in real time without waking the agent session or signaling completion. Only the reviewer's explicit click on the Host's **Handoff** button records a `review.handed_off` event, whose immutable payload is fetched as described in `references/reviewing.md`.

## Creating vs. Updating a hosted Taco

- **`publish` stays create:** `taco-cli publish <file.taco.html> --host <origin>` mints a brand-new hosted Taco entity with a new `tacoId` and distinct URL. Never use `publish` as a silent fallback when attempting to update an existing hosted Taco.
- **`update` replaces the active revision at the same URL:** `taco-cli update <tacoId> <file.taco.html> [--base <revisionId>] [--host <origin>]` posts a replacement revision to the existing `tacoId`. When `--base` is omitted, the CLI automatically reads the current `revisionId` from the Host's existing state; pass explicit `--base <revisionId>` to enforce an expected revision. The wire API still requires a base revision ID, which the CLI supplies in both cases. The hosted reviewer URL (`<origin>/t/<tacoId>`) stays stable; the Host records the returned new `revisionId`, preserves existing Host comment threads and Checkpoint statuses, and rejects the post when the base revision does not match the active Host state or when pending Host content recorded after the acknowledged Handoff diverges from what is being replaced—never overwriting it silently. Optional `--dry-run` remains entirely local; running `--dry-run` without `--base` performs a local projection without network requests and omits the base revision ID. A hosted Taco exposes only the shared URL and the revision identity; do not assume a per-revision URL that the Host does not actually serve.
- **Unsupported binary fallback guard:** If an older installed CLI does not support network update (or returns an unsupported error), report that network update is unsupported by the installed binary; **never** silently fall back to `publish` which would fragment the review into a new document and URL.

After a successful update, reload the same reviewer URL to read the new revision. Existing open tabs retain their local draft; a stale autosave is rejected by state-version checks.
## Retention and Expiration (TTL)

- **Default 30-day lifecycle:** Published Tacos are temporary by default and automatically expire after 30 days.
- **Custom duration:** Pass `taco-cli publish <file.taco.html> --ttl <duration>` to set an explicit expiration window (e.g. `--ttl 7d`, `--ttl 24h`, `--ttl 1h`, or `--ttl 0`/`--ttl none` for permanent within server limits).
- **Behavior after expiration:** Once a Taco expires, its reviewer URL (`/t/<tacoId>`), state, and event API endpoints return HTTP 410 Gone, and active event subscriptions terminate with `TACO_GONE`.
