## 适用场景

你让 Agent 写了一份设计方案，想在自己电脑上认真审一遍，把意见交回给 Agent 修改。全程只需要 [Taco Skill](../功能/02-Taco-Skill.md) 和浏览器。

## 1. 让 Agent 写方案并生成 Taco

```text
为「订单导出 CSV」写一份设计方案，包括需求、技术方案和接口，
放在 specs/order-export/，写完用 Taco 给我评审。
```

Agent 会在 `specs/order-export/` 下写好 Markdown（可能还有 Mermaid 流程图、OpenAPI 文件），然后打包成 `specs/order-export/order-export.taco.html`。

## 2. 打开 Taco

Agent 会给你一个可点击的文件链接，宿主允许时直接在浏览器里打开，并告诉你实际发生的是哪一种：

- **已给出链接**：你自己点开；
- **已打开**：浏览器里应该已经能看到；
- **已打开并验证**：Agent 还检查了页面正常加载。

## 3. 评审

### 提具体的意见

选中原文，点「评论」。意见越具体，Agent 越能一次改对：

| 模糊 | 具体 |
| --- | --- |
| 这里不太对 | 导出超过 10 万行时应改为异步任务，完成后发站内信，不要同步阻塞请求 |
| 接口再想想 | `GET /exports/{id}` 需要返回 `expiresAt`，前端要据此提示下载链接过期 |

### 直接改

错字、措辞、显而易见的小问题，直接在正文里改，比写评论更快。

### 评论图和代码

流程图里的某个节点、代码块里的某一行，都可以单独评论。Agent 收到时会知道你指的是哪个节点、哪一行。

## 4. 交接

点右上角「交接改动」，Taco 把这一轮结果复制到剪贴板，不需要先保存。粘贴给 Agent，它收到的大致是这样：

```markdown
我已在 Taco 评审页面完成了修改与评论，请同步以下变更：
- 文档标题: "order-export"

## 修改
--- specs/order-export/spec.md
+++ specs/order-export/spec.md
@@ -12 +12 @@
-导出文件保留 7 天。
+导出文件保留 3 天。

## 评论
- [specs/order-export/plan.md:18] 原文: "导出在请求内同步生成"
  - **lin**: 超过 10 万行时应改为异步任务，完成后发站内信。
```

另一种方式：点「保存」把改动写回 `.taco.html`，再告诉 Agent 去读这个文件。

## 5. Agent 处理

Agent 会：

1. 把每处修改和每条评论对应到仓库里的源文件；
2. 修改源文件，并说明每条意见是改了、只做了解释，还是需要你决策；
3. 刷新**同一个** Taco 并重新打开。

如果打包之后源文件又被别人改过，或某处修改无法干净应用，Agent 会报告冲突并停下来，不会悄悄覆盖。

## 6. 核对第二轮

重新打开的 Taco 文档身份不变，评论线程都还在：

- 回到每条评论，看对应的原文是否已经按意见修改；
- 满意就点「解决」；
- 不满意就在线程里回复，进入下一轮交接。

Agent 不会替你把评论标成已解决，关闭讨论始终由人决定。

## 常见问题

**没保存就关了浏览器怎么办？**
有未保存改动时，关闭页面前会提醒你。「交接改动」本身不需要先保存，复制出去的内容就是完整的这一轮结果。

**Agent 报告冲突是什么意思？**
你评审的是打包那一刻的内容。如果之后源文件又被修改，你的意见可能已经不适用，Agent 会把具体冲突和 diff 给你，由你决定怎么处理。

**用 Complete 还是 Lite？**
文件只在自己电脑上看，或要发给可能离线的人，用 Complete；能联网、在意文件体积，用 Lite。见 [Taco](../功能/01-Taco.md)。
