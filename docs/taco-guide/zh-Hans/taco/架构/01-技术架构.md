## 总览

Taco 由四层组成：一个自带应用的 HTML 容器、浏览器里的运行时、一份文件协议，以及可选的宿主。

组件关系见 [系统组件图](02-系统组件.mmd)，人和 Agent 的往返时序见 [评审往返时序](03-评审往返.mmd)。

## 容器：shell + 数据块

一个 `.taco.html` 分成两部分：

- **shell**：压缩内嵌的应用代码（阅读器、编辑器、评论、导航），对所有 Taco 都相同；
- **数据块**：`<script type="application/taco+json" id="taco-document">` 里的一段 JSON，装着这个议题的全部文档和评审状态。

Agent 生成或刷新 Taco 时，只复制 shell、写入数据块和 `<title>`，从不修改 shell 的其余部分。因此升级 shell 和更新内容互不干扰。

| shell | 体积 | 依赖 |
| --- | --- | --- |
| Complete | 约 2.7 MB | 内嵌 Tiptap、highlight.js/lowlight、Mermaid，完全离线 |
| Lite | 约 180 KB | 启动时从公共 CDN 加载锁定版本的依赖 |

## 协议：taco/files v1

数据块的格式是 `taco/files` 第 1 版，主要字段：

| 字段 | 说明 |
| --- | --- |
| `docId` | 文档身份。首次生成时创建，此后每次刷新都保留 |
| `root` | 文档目录的相对根路径 |
| `files[]` | 每个文件的路径、类型、内容，以及打包时的 `sourceHash` |
| `comments[]` | 评论线程：锚点、状态、消息 |
| `navigation` | 可选：入口文档与分组 |
| `checkpoints` | 可选：阶段图与文档状态 |
| `access` | 可选：设为 `reader` 时只读 |

完整示例见 [数据块示例](05-数据块示例.json)，各对象关系见 [数据模型](04-数据模型.mmd)。

刷新时必须原样保留 `docId`、`comments`、`navigation`、`checkpoints` 和所有不认识的字段——这是「同一个 Taco」能跨轮次延续的前提。

## 运行时

- **导航**：从文件路径推导目录和分类，或按 `navigation` 清单分组；
- **渲染**：Markdown 用 Tiptap 所见即所得编辑，JSON/YAML/Mermaid 走结构化查看器；目录、大纲、搜索索引都是派生数据，不单独保存；
- **评论**：锚点记录字符位置和前后文，原文变动后按上下文重新定位，失效时标记为过期而不是丢弃；
- **改动追踪**：与打开时的基线比较，生成「交接改动」需要的 diff；
- **保存**：浏览器支持时原地写回文件，否则下载副本。

## 往返与冲突

1. 打包时，每个文件记录内容的 SHA-256（`sourceHash`），作为「评审者看到的版本」；
2. 交接内容包含改动 diff 与未解决的评论；
3. Agent 应用前，比较仓库里的当前文件与 `sourceHash`：如果源文件在打包后又被修改，或 diff 无法干净应用，就报告冲突并停止，不覆盖任何一方。

## 宿主

- **本地**：直接用 `file://` 打开，不需要任何服务；
- **Tacobin**：实现 `taco-host/1` 协议，负责发布、自动保存、在线状态和交接事件。接口见 [Tacobin API](06-Tacobin-API.yaml)。

安全相关的约束见 [安全](07-安全.md)。
