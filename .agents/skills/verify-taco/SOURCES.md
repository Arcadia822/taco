## Decisions

- Class `workflow-process`, shape `script-backed-workflow`: lifecycle plus loopback serving is fragile boilerplate and belongs in an executable helper; feature recipes stay data in the map. Simpler inline guidance rejected: cleanup/evidence semantics must be identical across cold agents.
- Standalone Complete/Lite cases live in the browser registry (51 cases across browse, edit, comments, save, checkpoints and variants). Agent CLI behavior is covered by the ad-hoc `scripts/cli.mjs` scenario and the existing toolbox/Host lifecycles. Invoke the CLI scenario through `verify.mjs --scenario` after the CLI build; it is not registered in the browser suite or selected by `npm run test:verify`. Current CI invokes it in a separate post-build step. A browser pass does not prove an unexecuted CLI or Host operation.
- Loopback HTTP is the sanctioned headless channel (Codex must not autonomously navigate `file://`). The helper owns the ephemeral port and blocks extra origins by default.
- Headless `showSaveFilePicker` disable is confined to the save scenario as an explicit production-boundary override; native directory-write verification is out of scope.
- Generate fixture data with navigation, graph/instructions/missing requirement and multiple formats from the current shells. Keep source shells immutable and replace only `#taco-document`; use the same fixture manifest across cases and local Host publication.
- Race every setup await against an explicit cancellation promise and parse machine payloads in full. A close cannot be trusted to settle an in-flight `newPage()`, and a truncated stdout tail cannot round-trip the CLI's JSON receipt.
